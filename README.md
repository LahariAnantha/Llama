# Repository Structure and File Naming Conventions

## 1. Repository Overview

This repository contains the datasets, Python scripts, and documentation for our project investigating the relationship between inflation, unemployment, and consumer spending in the United States.

The project uses three publicly available economic datasets:

- **FRED Consumer Price Index (CPIAUCSL):** Monthly Consumer Price Index data used to measure changes in consumer prices.
- **U.S. Census Monthly Retail Trade Survey (MRTS):** Monthly retail and food services sales estimates used to measure consumer spending.
- **Bureau of Labor Statistics (LNS14000000):** Monthly civilian unemployment rates used to measure labor market conditions.

The repository is organized to support reproducibility, data quality assessment, cleaning, integration, and analysis.

## 3. Directory Descriptions

### `data/raw/` — Original Datasets

Contains the original datasets downloaded from the three government data sources. These files are preserved without modification to maintain traceability and support data integrity verification.

- **`cpi.csv`:** Original Consumer Price Index observations from FRED.
- **`mrts.csv`:** Original Census MRTS dataset containing multiple retail categories and statistical measures.
- **`unemployment.json`:** Original BLS unemployment API response.

### `data/processed/` — Cleaned and Integrated Datasets

Contains datasets generated by the cleaning and integration scripts.

- **`cpi_clean.csv`:** CPI data with standardized dates and numeric values, with invalid or missing observations excluded.
- **`retail_clean.csv`:** Seasonally adjusted monthly retail and food services sales for the selected category.
- **`unemployment_clean.csv`:** Monthly unemployment rates with standardized dates and valid numeric observations.
- **`integrated.csv`:** Combined dataset containing CPI, retail sales, and unemployment observations joined by month.
- **`summary_statistics.csv`:** Descriptive statistics for CPI, unemployment rates, and retail sales.
- **`correlations.csv`:** Pearson correlation matrix for the three economic metrics.

### `scripts/` — Data Processing Scripts

Contains the Python scripts responsible for the data pipeline.

| Script | Description |
|---|---|
| `acquire_data.py` | Downloads the original datasets from their respective government sources. |
| `verify_integrity.py` | Performs integrity checks to verify downloaded data files. |
| `profile_data.py` | Profiles datasets to identify missing values, duplicates, inconsistencies, and other potential data quality issues. |
| `clean_data.py` | Cleans and standardizes the three datasets, validates observations, and saves processed CSV files. |
| `integrate_data.py` | Joins the three cleaned datasets using the common monthly date attribute. |

| `initial_analysis.py` | Calculates descriptive statistics and Pearson correlations, saving the results as CSV files. |
| `initial_visualization.py` | Generates the CPI vs. retail sales scatterplot and monthly metric trend visualization. |
| `run_all.py` | Executes the profiling, cleaning, integration, analysis, and visualization scripts in sequence. |



### `data/checksums/` — Raw Data Checksums

Contains the SHA-256 checksum files for the three original datasets.

### `figures/` — Visualizations

Contains the scatterplot and monthly trends visualization generated by `initial_visualization.py`.

## 5. File Naming Conventions

To maintain consistency and readability across the repository, the following naming conventions are used:

- **Python scripts:** Lowercase snake_case names describing their purpose, such as `clean_data.py` and `integrate_data.py`.
- **Raw datasets:** Descriptive names reflecting the original source or dataset, such as `cpi.csv`, `mrts.csv`, and `unemployment.json`.
- **Processed datasets:** Lowercase names with the suffix `_clean.csv` to distinguish them from the original files.
- **Column names:** Lowercase snake_case, such as `sales_millions` and `unemployment_rate`.
- **Date values:** Standardized to `YYYY-MM-DD`, with the first day of the month representing each monthly observation.
- **Documentation:** Markdown files (`.md`) containing descriptive titles and structured headings.

## 6. Data Organization and Integration

The project uses Python and pandas rather than a relational database because the three datasets consist of relatively small, structured monthly time series.

The common integration attribute is `date`, which allows the datasets to be joined using a one-to-one relationship between monthly observations.

The retail dataset currently covers January through December 2025. Therefore, the integration focuses on months within this period that also contain valid CPI and unemployment observations.

The resulting integrated dataset is stored as a CSV file for subsequent statistical analysis and visualization.

## 7. Reproducibility

The project follows modular design with numerous Python scripts that together form a comprehensive workflow for raw data processing, cleaning, profiling, integrating, analyzing, and visualizing. Beyond this there is documentation on the various processing scripts to maintain transparency in the operations conducted on the data and their impacts to ensure that the work is reproducible.

### Setup 

The project requires Python3 and the dependencies are listed in the `requirements.txt`. 

For usage, clone the repository, navigate to the main project folder and install the dependencies with the following command: 

``` bash
python3 -m pip install -r requirements.txt
```

### Running the Data Workflow

The entire workflow for data cleaning, validating, integrating, analyzing, and visualizing can be executed with a single command from the root of the repository with the following command: 

```bash
python3 scripts/run_all.py
```

This will execute the scripts in the order intended for processing from raw data through to the analysis and visualization stage. If the scripts encounter errors at any stage, the process will halt. Once the workflow has executed successfully the message `Workflow completed successfully!` will be printed.

The intended automated workflow follows these stages:

1. Acquire original datasets.
2. Verify data integrity.
3. Profile datasets and assess data quality.
4. Clean and standardize source data.
5. Integrate datasets using the common monthly date.
6. Leverage the integrated dataset for analysis and visualization.

The processed datasets can be regenerated without modifying the original source files.

### Running the Workflow Individually

If instead it is desired or required to run each script independently. They must be done so in the following order with the following command: 

```bash
python3 scripts/profile_data.py
python3 scripts/clean_data.py
python3 scripts/integrate_data.py
python3 scripts/initial_analysis.py
python3 scripts/initial_visualization.py
```
